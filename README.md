# Хомяк - исходный код

«Хомяк: учёт денег» - приложение для Android: кошельки, доходы и расходы, месячные лимиты по категориям и аналитика. Приложение в RuStore: https://www.rustore.ru/catalog/app/ru.dorokhin.homyak

Здесь лежит исходный код версии 1.0.2 (versionCode 20005), той же, что опубликована в RuStore.

## Зачем код открыт

Приложению, которому доверяют свои деньги, нельзя верить на слово. Код открыт, чтобы любой мог сам проверить: данные не уходят в сеть, скрытой рекламы и слежки нет, покупка работает только через RuStore. Все утверждения ниже можно сверить с файлами, на которые они ссылаются.

## Как устроено приложение

Это Capacitor-приложение. Интерфейс и вся логика написаны на обычном JavaScript без фреймворков (папка `www/`) и работают внутри WebView. Нативная часть на Java (папка `android/`) - это оболочка, окно сохранения файла и мост к оплате RuStore.

- `www/engine.js` - расчёты: балансы кошельков, факт и план по категориям, аналитика. Чистые функции без обращений к сети и хранилищу.
- `www/ui.js`, `www/edit.js`, `www/sheet.js`, `www/summary.js` - экраны.
- `www/pay.js`, `www/purchase.js`, `www/license.js` - полный доступ: покупка и ключ.
- `www/backup.js` - резервная копия в файл и восстановление.

## Где хранятся данные

- Все кошельки, категории, лимиты и операции хранятся в одном месте: в хранилище WebView (`localStorage`) под ключом `homyak_v1`, внутри приватной папки приложения на телефоне. См. `www/ui.js`, строка 19 (ключ) и строки 98-112 (запись).
- Сервера у приложения нет, регистрации и аккаунта нет. Данные не шифруются: защищает их песочница Android, как и данные любого другого приложения.
- Данные не попадают в облачную резервную копию Android и не переносятся при смене телефона: `allowBackup="false"` и правила `data_extraction_rules.xml`. См. `android/app/src/main/AndroidManifest.xml`, строки 4-9, и `android/app/src/main/res/xml/data_extraction_rules.xml`.
- Резервная копия, которую делает сам пользователь (`Хомяк-бэкап-ДАТА.json`), - обычный JSON-файл со всеми данными. Он сохраняется только туда, куда пользователь сам укажет в системном окне сохранения. См. `www/backup.js`, строки 57-64, и `android/app/src/main/java/ru/dorokhin/budgetphone/SaveFilePlugin.java`.

## Сетевые обращения

Ниже все места, где приложение может обратиться к сети.

1. **RuStore Pay** (покупка полного доступа). Нативный SDK RuStore (`ru.rustore.sdk:pay`) используется для оплаты и для проверки, куплен ли полный доступ. Данные пользователя в эти вызовы не передаются, только идентификатор товара `full_access`. Что SDK передаёт серверам RuStore (включая его собственные технические метрики), определяет RuStore. См. `android/app/src/main/java/ru/dorokhin/budgetphone/RuStorePayPlugin.java`, `www/pay.js`, строки 25-26, `android/app/build.gradle`, строки 76-77.
2. **Проверка номера версии** (`www/update.js`). Раз в неделю и по кнопке «Проверить» в меню приложение запрашивает файл `https://dorokhin-finance.ru/homyak-store/update.json` и сравнивает номер версии со своим (строка 49, строки 283-308, 611-639). Запрос - обычный GET без параметров, сведения о пользователе и его данные не отправляются. Если есть новая версия, приложение показывает окно с кнопкой «Открыть в RuStore».
3. **Код обновляется только через RuStore.** В сборке для RuStore скачивание и подмена кода выключены: окна обновления ведут только в RuStore (строки 472 и 505), а сама функция подмены отказывается работать ещё до любых действий (строки 702-707). Нативная оболочка на старте дополнительно забывает путь к любой скачанной ранее веб-сборке. См. `android/app/src/main/java/ru/dorokhin/budgetphone/MainActivity.java`, строки 12-20.
4. **Ссылки, которые открывает сам пользователь.** Политика конфиденциальности, пользовательское соглашение и сайт автора в окне «О приложении» открываются в системном браузере. Само приложение при этом ничего не загружает.

Других сетевых вызовов (`fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`) в коде приложения нет, кроме `www/update.js`: в нём запрос манифеста (строка 293) и загрузка файлов бесшовного обновления (строки 852 и 869), которая в сборке для RuStore не выполняется (пункт 3). Сторонних библиотек аналитики, рекламы и отчётов о сбоях нет: зависимости видны в `package.json` и `android/app/build.gradle`. Проверить:

```
grep -rn "fetch\|XMLHttpRequest\|WebSocket\|sendBeacon" www --include=*.js
```

(`www/vendor/` - библиотека распаковки fflate, `www/capacitor.js` - мост Capacitor.)

## Разрешения Android

Итоговый список из APK версии 1.0.2 (`aapt dump permissions`):

- `INTERNET` - покупка и проверка покупки через RuStore Pay, проверка номера версии (см. выше).
- `VIBRATE` - лёгкая вибрация при перетаскивании и записи операции.
- `ACCESS_NETWORK_STATE`, `RECEIVE_BOOT_COMPLETED` - добавляет библиотека метрик внутри RuStore Pay SDK (`ru.rustore.sdk:metrics`), приложение их само не использует.
- `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` - служебное разрешение библиотеки AndroidX, защищает внутренние сообщения приложения от других приложений.

В исходнике объявлены только `INTERNET` и `VIBRATE` (`android/app/src/main/AndroidManifest.xml`, строки 69-70), остальные добавляют библиотеки при сборке. Доступа к контактам, камере, геолокации, SMS и файлам телефона у приложения нет.

## Полный доступ

- Бесплатная версия ограничена: 2 кошелька, 8 категорий расходов, 1 источник дохода, часть аналитики. Созданное не блокируется. См. `www/engine.js` (`FREE`, `canAddWallet`, `canAddExpCat`, `canAddIncCat`).
- Полный доступ покупается один раз через RuStore Pay. После переустановки он восстанавливается сам, если войти в тот же аккаунт RuStore.
- Лицензионный ключ проверяется офлайн по подписи ECDSA P-256 через стандартный WebCrypto. В приложение вшит только публичный ключ, подделать ключ, разобрав APK, нельзя. См. `www/license.js`, строки 1-30.

## Чем исходник отличается от сборки в RuStore

Скрипт `node build-apk.js --store` делает копию папки `www/` и меняет в ней две вещи: вставляет в `index.html` строку с флагами сборки (`HOMYAK_FULL_ACCESS=false`, `HOMYAK_DEMO=false`, `HOMYAK_PAY=true`, `HOMYAK_STORE=true`) и убирает подключение отладочного `selftest.js`. Отладочные файлы (`selftest.js`, `icons.html`, `preview.html`, `icon-512.png`, `sounds/README.txt`) в APK не попадают. Остальные файлы попадают в APK без изменений. См. `build-lib.js`, строка 22 и строки 59-100.

Сверено перед публикацией: содержимое `assets/public/` в APK версии 1.0.2 совпадает с папкой `www/` этого репозитория с точностью до этих отличий, файлов `cordova.js` и `cordova_plugins.js`, которые добавляет Capacitor, и звуков `www/sounds/*.mp3`: они есть в APK, но в репозиторий не выложены. Без них приложение работает так же, только без звука (см. `www/sound.js`).

## Как проверить самому

1. **Режим полёта.** Включите режим полёта и пользуйтесь приложением: запись операций, кошельки, лимиты, аналитика и резервная копия работают без сети. Без сети не сработают только покупка, восстановление покупки и проверка номера версии.
2. **Найти сетевые вызовы.** Команда из раздела «Сетевые обращения».
3. **Запустить тесты.** Нужен Node.js 20 или новее:

   ```
   npm install
   npm test
   ```

   На момент публикации: 380 проверок, 373 проходят, 0 падают, 7 пропускаются. Двум нужен настоящий лицензионный ключ автора, одной - его приватный ключ подписи, четырём - внутренние скрипты публикации обновлений: в репозиторий они не входят (причина пропуска печатается рядом с проверкой). Часть проверок запускает приложение в Microsoft Edge без окна (headless), для них нужен установленный Edge. Остальные проверки лицензии работают на ключе от свежей пары ключей, а `tests/no-issued-keys.test.js` следит, чтобы в репозиторий не попал ни один настоящий ключ.

## Сборка APK

`node build-apk.js` собирает тестовый APK (нужны JDK 17 и Android SDK). В тестовой сборке демо-данные и полный доступ включены для проверки. Релизная сборка подписывается ключом автора, которого здесь нет, поэтому подпись вашего APK не совпадёт с приложением из RuStore.
