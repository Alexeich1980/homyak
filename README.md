# Хомяк - исходный код

«Хомяк: учёт денег» - приложение для Android: кошельки, доходы и расходы, месячные лимиты по категориям и аналитика. Приложение в RuStore: https://www.rustore.ru/catalog/app/ru.dorokhin.homyak

Здесь лежит исходный код версии 1.0.5 (versionCode 20011), той же, что опубликована в RuStore.

## Зачем код открыт

Приложению, которому доверяют свои деньги, нельзя верить на слово. Код открыт, чтобы любой мог сам проверить: данные не уходят в сеть, скрытой рекламы и слежки нет, покупка и обновления работают только через RuStore. Все утверждения ниже можно сверить с файлами, на которые они ссылаются.

## Как устроено приложение

Это Capacitor-приложение. Интерфейс и вся логика написаны на обычном JavaScript без фреймворков (папка `www/`) и работают внутри WebView. Нативная часть на Java (папка `android/`) - это оболочка, окно сохранения файла, окно «Отправить» для таблицы Excel, локальные напоминания о платежах и мосты к RuStore (оплата, проверка обновления, окно оценки).

- `www/engine.js` - расчёты: балансы кошельков, факт и план по категориям, долги, аналитика. Чистые функции без обращений к сети и хранилищу.
- `www/ui.js`, `www/edit.js`, `www/sheet.js`, `www/summary.js`, `www/picker.js` - экраны и окна выбора даты и списков.
- `www/debts.js` - долги и кредитные карты: экраны и напоминания о платежах.
- `www/xlsx.js` - выгрузка в Excel, `www/import.js` и `www/import-ui.js` - загрузка операций из таблиц других приложений.
- `www/pay.js`, `www/purchase.js`, `www/license.js` - полный доступ: покупка и ключ.
- `www/backup.js` - резервная копия в файл и восстановление.
- `www/lock.js`, `www/guards.js` - защита входа кодом и отпечатком.
- `www/nudges.js` - окно оценки RuStore и напоминание сохранить копию.
- `www/glow.js` - подсветка экрана при перерасходе и доходе (только анимация, без сети и хранилища).
- `www/update.js` - проверка обновления.

## Где хранятся данные

- Все кошельки, категории, лимиты и операции хранятся в одном месте: в хранилище WebView (`localStorage`) под ключом `homyak_v1`, внутри приватной папки приложения на телефоне. См. `www/ui.js`, строка 19 (ключ) и строки 115-156 (запись).
- Перед загрузкой операций из таблицы приложение кладёт в то же хранилище копию данных под ключом `homyak_v1.preimport`, чтобы последнюю загрузку можно было отменить. См. `www/import-ui.js`, строка 11, и `www/ui.js`, строки 132-145.
- Напоминания о платежах по долгам и кредитным картам (по желанию, тумблер в карточке долга) - локальные уведомления Android, без сервера. План напоминаний (даты, название долга и текст без сумм) приложение отдаёт оболочке, она хранит его в приватных настройках приложения (`SharedPreferences` с именем `homyak_reminders`) и ставит будильник `AlarmManager`. На заблокированном экране видна только общая строка без названия долга. См. `www/engine.js`, строки 1893-1946 (`reminderPlan`), `www/debts.js`, строки 1-16 и 867, `android/app/src/main/java/ru/dorokhin/budgetphone/ReminderPlugin.java`, строки 23-43, `ReminderReceiver.java`, строки 32 и 145-178.
- Сервера у приложения нет, регистрации и аккаунта нет. Данные не шифруются: защищает их песочница Android, как и данные любого другого приложения.
- Данные не попадают в облачную резервную копию Android и не переносятся при смене телефона: `allowBackup="false"` и правила `data_extraction_rules.xml`. См. `android/app/src/main/AndroidManifest.xml`, строки 4-9, и `android/app/src/main/res/xml/data_extraction_rules.xml`.
- Резервная копия, которую делает сам пользователь (`Хомяк-бэкап-ДАТА.json`), - обычный JSON-файл со всеми данными. Он сохраняется только туда, куда пользователь сам укажет в системном окне сохранения. См. `www/backup.js`, строки 11-13 и 112-124, и `android/app/src/main/java/ru/dorokhin/budgetphone/SaveFilePlugin.java`.
- Таблица Excel (полная версия) собирается на телефоне и уходит только в системное окно «Отправить», где пользователь сам выбирает, куда её передать. Файл лежит во временной папке `cache/export` приложения, право прочитать его получает одно выбранное приложение. См. `www/backup.js`, строки 146-203, `android/app/src/main/java/ru/dorokhin/budgetphone/ShareFilePlugin.java`, строки 21-39, и `android/app/src/main/res/xml/file_paths.xml`. Таблицу для загрузки пользователь выбирает сам в системном окне выбора файла, приложение читает её на телефоне: `www/import-ui.js`, строки 61-80.
- Защита входа (по желанию) хранит не сам код из 4 цифр, а его хэш PBKDF2-SHA256 с солью, в отдельном ключе `homyak-lock` того же хранилища. Вход по отпечатку проверяет система Android, отпечаток приложение не видит. Данные замок не шифрует. См. `www/lock.js`, строки 1-11 и 66-82, `www/guards.js`, строки 113-132.

## Сетевые обращения

В сборке для RuStore веб-часть приложения (весь код из `www/`) в сеть не ходит вовсе: при сборке в политику безопасности страницы вписывается `connect-src 'none'`, и WebView отклоняет любой `fetch`, `XMLHttpRequest` и `WebSocket` к любому адресу. См. `build-lib.js`, строки 82-102 (`shipCsp`), и `www/index.html`, строки 5-9 (в исходнике там адрес сайта автора: он нужен только тестовой сборке, см. ниже). Сборка не пройдёт, если в APK для RuStore сеть не закрыта: `build-lib.js`, строка 482.

В сеть выходят только нативные модули RuStore:

1. **RuStore Pay** (покупка полного доступа). Нативный SDK RuStore (`ru.rustore.sdk:pay`) используется для оплаты и для проверки, куплен ли полный доступ. Данные пользователя в эти вызовы не передаются, только идентификатор товара `full_access`. См. `android/app/src/main/java/ru/dorokhin/budgetphone/RuStorePayPlugin.java`, `www/pay.js`, строки 25-26, `android/app/build.gradle`, строки 87-88.
2. **Проверка обновления через RuStore** (`ru.rustore.sdk:appupdate`). Раз в неделю и по кнопке «Проверить» приложение спрашивает у установленного на телефоне RuStore, есть ли версия новее, и ставит её окном RuStore. Свой файл с номером версии сборка для RuStore не запрашивает. См. `www/update.js`, строки 1-11, 290-300 и 729-743, `android/app/src/main/java/ru/dorokhin/budgetphone/RuStoreUpdatePlugin.java`, `android/app/build.gradle`, строка 95.
3. **Окно оценки RuStore** (`ru.rustore.sdk:review`). Один раз, после удачной записи операции, приложение может показать системное окно оценки RuStore. См. `www/nudges.js`, строки 1-6, `android/app/src/main/java/ru/dorokhin/budgetphone/RuStoreReviewPlugin.java`, `android/app/build.gradle`, строка 91.
4. **Ссылки, которые открывает сам пользователь.** Политика конфиденциальности, пользовательское соглашение и сайт автора в окне «О приложении» открываются в системном браузере. Само приложение при этом ничего не загружает.

Что SDK RuStore передают серверам RuStore (включая их собственные технические метрики), определяет RuStore.

**Код обновляется только через RuStore.** В сборке для RuStore скачивание и подмена кода выключены: окна обновления в обход RuStore не открываются (`www/update.js`, строки 621 и 654), функция подмены отказывается работать до любых действий (строка 871), а папку от прежних бесшовных обновлений приложение убирает (строка 1107). Нативная оболочка на старте дополнительно забывает путь к любой скачанной ранее веб-сборке. См. `android/app/src/main/java/ru/dorokhin/budgetphone/MainActivity.java`, строки 17-28.

В коде `www/update.js` остался путь для тестовой сборки автора (своя проверка номера версии и бесшовное обновление с сайта автора): `fetchManifest` и `fetchBundle`, строки 401-465. В сборке для RuStore он не вызывается (строки 733 и 772) и не смог бы выйти в сеть из-за `connect-src 'none'`. Сторонних библиотек аналитики, рекламы и отчётов о сбоях нет: зависимости видны в `package.json` и `android/app/build.gradle`. Проверить:

```
grep -rn "fetch\|XMLHttpRequest\|WebSocket\|sendBeacon" www --include=*.js
```

(`www/vendor/` - библиотека распаковки fflate, `www/capacitor.js` - мост Capacitor, `www/selftest.js` - отладочная самопроверка, в APK не попадает; `fetch('files.json')` в `www/update.js` читает файл внутри самого приложения, и только в тестовой сборке.)

## Разрешения Android

Итоговый список из APK версии 1.0.5 (`aapt dump permissions`), такой же, как в 1.0.4:

- `INTERNET` - модули RuStore: покупка, проверка покупки, проверка обновления, окно оценки (см. выше).
- `VIBRATE` - лёгкая вибрация при перетаскивании и записи операции.
- `USE_BIOMETRIC`, `USE_FINGERPRINT` - вход по отпечатку в «Защите входа». Добавляет библиотека `androidx.biometric`, которую подключает плагин `capacitor-native-biometric`.
- `POST_NOTIFICATIONS` (с версии 1.0.4) - показ напоминаний о платежах по долгам и кредитным картам. Android 13+ спрашивает его только когда пользователь включает «Напомнить о платеже»: `www/debts.js`, строки 919-921.
- `RECEIVE_BOOT_COMPLETED` (объявлен приложением с версии 1.0.4, раньше его добавляла библиотека метрик RuStore Pay SDK) - после перезагрузки телефона заново поставить будильник напоминания по сохранённому плану. Приёмник закрыт для других приложений (`android:exported="false"`) и ничего не отправляет в сеть: `android/app/src/main/AndroidManifest.xml`, строки 57-70, `ReminderReceiver.java`.
- `ACCESS_NETWORK_STATE` - добавляет библиотека метрик внутри RuStore Pay SDK (`ru.rustore.sdk:metrics`), приложение его само не использует.
- `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` - служебное разрешение библиотеки AndroidX, защищает внутренние сообщения приложения от других приложений.

В исходнике объявлены `INTERNET`, `VIBRATE`, `POST_NOTIFICATIONS` и `RECEIVE_BOOT_COMPLETED` (`android/app/src/main/AndroidManifest.xml`, строки 95-102), остальные добавляют библиотеки при сборке. Точные будильники (`SCHEDULE_EXACT_ALARM`) не запрашиваются. Блок `<queries>` (строки 83-91) разрешением не является: он нужен, чтобы приложение видело установленный RuStore. Доступа к контактам, камере, геолокации, SMS и файлам телефона у приложения нет.

## Полный доступ

- Бесплатная версия ограничена: 2 кошелька, 8 категорий расходов, 1 источник дохода, 1 долг, часть аналитики; таблица Excel - только в полной версии. Созданное не блокируется. См. `www/engine.js`, строки 988-1004 (`FREE`, `canAddWallet`, `canAddExpCat`, `canAddIncCat`).
- Полный доступ покупается один раз через RuStore Pay. После переустановки он восстанавливается сам, если войти в тот же аккаунт RuStore.
- Лицензионный ключ проверяется офлайн по подписи ECDSA P-256 через стандартный WebCrypto. В приложение вшит только публичный ключ (`www/license.js`, строка 27), подделать ключ, разобрав APK, нельзя. См. `www/license.js`, строки 1-30.

## Чем исходник отличается от сборки в RuStore

Скрипт `node build-apk.js --store` делает копию папки `www/` и меняет в ней только `index.html`: вставляет строку с флагами сборки (`HOMYAK_FULL_ACCESS=false`, `HOMYAK_DEMO=false`, `HOMYAK_PAY=true`, `HOMYAK_STORE=true`), закрывает сеть (`connect-src 'none'`) и убирает подключение отладочного `selftest.js`. Отладочные файлы (`selftest.js`, `icons.html`, `preview.html`, `icon-512.png`, `sounds/README.txt`) в APK не попадают. Остальные файлы попадают в APK без изменений. См. `build-lib.js`, строка 22 и строки 94-136.

Сверено перед публикацией: копия, которую `makeShip` из `build-lib.js` собирает из папки `www/` этого репозитория в режиме RuStore, совпадает с содержимым `assets/public/` в APK версии 1.0.5 файл в файл, кроме файлов `cordova.js` и `cordova_plugins.js`, которые добавляет Capacitor, и звуков `www/sounds/*.mp3`: они есть в APK, но в репозиторий не выложены. Без них приложение работает так же, только без звука (см. `www/sound.js`).

## Как проверить самому

1. **Режим полёта.** Включите режим полёта и пользуйтесь приложением: запись операций, кошельки, лимиты, долги, аналитика, защита входа, напоминания о платежах, резервная копия и таблица Excel работают без сети. Без сети не сработают только покупка, восстановление покупки, проверка обновления и окно оценки.
2. **Найти сетевые вызовы.** Команда из раздела «Сетевые обращения».
3. **Запустить тесты.** Нужен Node.js 20 или новее:

   ```
   npm ci
   npm test
   ```

   На момент публикации: 705 проверок, 689 проходят, 0 падают, 16 пропускаются. Двум нужен настоящий лицензионный ключ автора, одной - его приватный ключ подписи, остальным - внутренние скрипты и файлы автора (публикация обновлений, картинки для витрины RuStore, стенд скриншотов экрана, исходный лист иконок): в репозиторий они не входят, причина пропуска печатается рядом с проверкой. Проверка `no-desktop-litter.test.js` касается только скриптов картинок витрины и в репозиторий не включена. Проверка скорости экрана капитала (`tests/wallets-b2.test.js`, «быстрее 20 мс») меряет время и на медленном или загруженном компьютере может не уложиться в порог. Часть проверок запускает приложение в Microsoft Edge без окна (headless), для них нужен установленный Edge. Остальные проверки лицензии работают на ключе от свежей пары ключей, а `tests/no-issued-keys.test.js` следит, чтобы в репозиторий не попал ни один настоящий ключ.

## Сборка APK

`node build-apk.js` собирает тестовый APK (нужны JDK 17 и Android SDK). В тестовой сборке демо-данные и полный доступ включены для проверки. Релизная сборка подписывается ключом автора, которого здесь нет, поэтому подпись вашего APK не совпадёт с приложением из RuStore.
